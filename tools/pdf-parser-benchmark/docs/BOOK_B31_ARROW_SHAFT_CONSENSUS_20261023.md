## 本次实施

新 `ebook_b31_arrow_shaft_consensus.py` 完全独立于 GLM，仅读取之前由**原始 PDF 图像**生成的 source-only OpenCV 私有报告，且先对源 PNG、Manifest SHA、原始物理页、OpenCV 报告来源摘要和可信声明进行一致性验证。

确定性几何流程：

1. 对原有 Hough 候选做有界共线分组：夹角差约 5° 内、横向偏移至多 6 像素、纵向间隔至多 28 像素，试图把被文字/印刷间隙中断的短线段拼成较长线索。
2. 对检测到的三角形，仅按几何最长边确定**暂定底边**，相反顶点作为暂定尖端；用边长与细长比拒绝退化的三角形。
3. 不再只比较线端与三角形**中心**，而是比较线端距**三角形底边中点**的距离，并检查轴向向量与底边→尖端的方向夹角。保留近邻但被方向一致性拒绝的数量。
4. 将线段、三角形以及通过多个约束的配对，以有限的私有 JSON 结构保存；凡无法识别者继续 `UNVERIFIED`，不修改候选模型记录和源像素。

以上计算只输出匿名**数量**到 GitHub Actions；坐标、源 SHA、原始页面、图文本、模型回复及其它可识别信息仅在 D 盘原有私有 Benchmark 下保留。

## 强制边界

- 所有输入线段和三角形坐标都验证为有限尺寸内整数；最多 256 条原始线段、128 个三角形、128 个输出配对。源图片像素最多 400 万，不生成新增模型请求。
- 合成用例涵盖：短线段断裂后合并／三角形底边与线段方向正确、三角尖端反向拒绝、图中文字噪声与不相关三角形拒绝、边界坐标拒绝、GLM 候选完全不读取、私有报表独占创建、源 SHA 错误与假认证拒绝。
- Windows Runner **不注入任何 GLM key**；对前 8 件 B15/B31 私有来源、解析、预测材料逐一 SHA 核验前后不变。只有零写入预检 PASS 才独占生成 `b31_arrow_shaft_consensus.private.json`。
- 若实际匹配为 0，必须如实记录「当前几何算法仍未确认箭头」，不可改阈值直到看见满足质量条件的独立源图像复核证据。若匹配多于 0，也只是几何候选，**不是箭头方向人工正确率、不是完整图结构金标准**。
