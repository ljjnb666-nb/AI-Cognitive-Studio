# 恢复全书综合后的余额不足诊断

## 真实结论

用户恢复后新执行记录返回INVALID_PROVIDER_REQUEST，约247毫秒失败。历史日志没有保存拒绝详情，不能据此认定参数不兼容。

本轮通过正常单书任务请求边界、有效执行快照、Gateway授权和现有预算保护，限定最多一条真实文本HTTP请求、不重试。实际服务商返回HTTP402，error.type为insufficient_balance_error，错误说明匹配余额不足。不是新的长度截断或审核拒绝。供应商未报告Token用量，无法确认人民币实扣，未宣称免费。

一次本地诊断准备曾误用旧语义Run的执行快照，触发ROUTE_PLAN_INTEGRITY保护，发送0次HTTP；该失败记录保留。随后使用先前正常恢复任务中校验通过的完整执行快照做诊断，才发出上述唯一一条HTTP请求。没有绕过完整性门禁或修改旧快照。

## 修复

- HTTP402正确归为QUOTA_EXCEEDED，停止而不自动重试。
- 只保存安全计费诊断HTTP状态与固定原因分类，不把供应商原始说明、正文或密钥写入日志。
- 中文页面区分“服务商余额或计费额度不足”“本机处理额度不足”和“服务商拒绝请求参数”。
- 当前诊断任务的失败摘要已依据加密HTTP回执离线校正为余额不足；任务错误内保留previousError及诊断来源，供应商调用、失败尝试、旧任务和费用账本不改写。校正前摘要另存私有备份。
- 原始HTTP错误回执加密保存在私有目录，未提交Git。

## 验证

Gateway适配器单元58/58；中文状态28/28；隔离PostgreSQL错误账本与幂等回放6/6，共92项。Gateway及Web类型检查、修改范围ESLint和差异检查通过。实际组件Playwright检查显示中文余额原因、无原始英文编号和页面异常；Browser plugin not available，使用Playwright。

278个CHUNK和1个成功综合批次保持不变。没有额外向量、音频、视频或OCR调用，没有自动充值、切换模型或继续重试。全书仍未成功完成。

## 剩余阻塞

服务商账户余额/计费状态需要账户持有人处理。本机取消单任务限制或继续提高输出额度不能补足服务商余额。处理后可通过正常恢复入口复用现有成果继续综合；实际生成成功仍需后续验证。
