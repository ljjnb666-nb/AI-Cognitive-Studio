# 保留思考的分块输出截断修复

## 真实原因

本机历史失败记录显示 MiniMax-M3 在分块理解阶段返回 HTTP 200，结束原因 LENGTH，输出用量16000词元；思考字段47377字符，最终答案4987字符且不是完整JSON。不是本次内容审核拒绝。原回执及用量记录保留，实际人民币扣费未知。

## 最终修复

按用户明确要求保留思考。未向 MiniMax-M3 发送 thinking.disabled、reasoning_effort 或思考预算参数，也没有删除或截取思考内容来伪造有效答案。

分块请求总输出上限从16000提高至32000；思考和最终答案共用此额度，无法声称分别限额。分块等待上限从300秒提高至600秒，数据库执行租约为630秒，并发控制租约同步覆盖等待时间。归并与全书综合仍为16000/300秒。每请求仍最多1次，不因截断自动重试，不切换模型。摘要和记忆内容增加简洁输出要求，原文、来源范围和引用门禁保持。

新增 OUTPUT_TRUNCATED 明确分类，即使截断内容恰巧是合法JSON也不接受。失败用量与安全诊断仍落库。旧记录不改写；旧 INVALID_PROVIDER_RESPONSE 显示“模型返回格式异常”，新截断分类显示“模型输出被截断”。前端统一使用“错误类型”及固定中文映射，未知编号不会原样显示。

官方依据：https://platform.minimax.io/docs/api-reference/text-openai-api （2026-11-06核验：思考计入总输出，M3与M3.1参数不同）。
