# PDF 第二阶段｜Docling 任务租约心跳（PR #191）

## 基线与实际改变

在 #190 PostgreSQL 持久任务 + 令牌抢占 + 结果事务屏障的基础上，增加 **60 秒周期的数据库时钟续租**，覆盖读取源 PDF、离线 Docling 推理、私有对象存储写入和候选快照事务。原有初始租约 300 秒，每次续租仅当前有效 token 可更新为 DB NOW()+300 秒；SQL 条件包含 RUNNING、令牌、attemptCount 和未过期租约。

续租过程严格串行，不允许多个心跳重叠；在工作完成或失败时清理定时器并等待已经开始的续租操作结束，然后才允许结算任务。这防止“模型返回得比最后一次续租快，先把结果判成功”的竞态。

任何续租失败、数据库联通错误或令牌已经失效均保守报 `DOCLING_LAYOUT_HEARTBEAT_LOST`，**不能把该次模型输出判为成功**。快照真实 DB 写入仍使用 #190 的 `SELECT ... FOR UPDATE` 令牌/租约/租户/页码/模型来源核验，不以心跳代替提交屏障。

## 回归测试

在原有 Worker 单测套件追加六项：心跳参数门禁、成功续租与停止后不再操作数据库、过期 owner 拒绝、数据库断连保守拒绝、工作本身出错后安全清理、已有续租未完成不能放行结果。

真实 PostgreSQL 中扩展“两个 Worker 接管同一任务”的集成测试：owner A 续期成功；强制让租约过期后续期失败；owner B 接管并续期成功；owner A 即使重放也不能续期、结算或写入快照；owner B 终态提交后也不能再续期。

## 范围限制

- Docling 候选后台任务依旧**默认关闭**（`DOCLING_LAYOUT_ENABLED=false`），不修改生产 PDF.js/RapidOCR 正文、当前提取指针和分析 Outbox。
- 心跳只延续**单个来源页/模型任务的执行权**，不提供全局 CPU 资源信号量；多个主机仍可能同时分析不同页面。跨主机容量租约需要下一独立切片。
- 目前没有完整真实 Docling Python + Redis + PG + S3 **同一次**运行的证据，不能宣称生产多引擎架构已经冻结。
- Redis 仍只负责投递，PG 保留两次总预算。独立五书 gold 0/5，CER=null，Issue #161 OPEN。
- 上游和本 PR 全部保持 Draft/Open/Unmerged，不得未经用户明确授权合并。
