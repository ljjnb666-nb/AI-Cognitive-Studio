# 书籍理解：备用模型第一次切换的原子预留（暂不发送付费调用）

## 目的和已验收基线

承接 #245–#250 主干已有的模型路由偏好、冻结计划、逐操作账本和发送前加密回执恢复。此前未实现真实的备用候选切换预留，因此需要将**独立追加收费授权**、**前次远端确认未发送**和**预算**放进同一数据库事务，而不能仅依据错误代码切模型。

## 本次代码

新增 `BookFailoverPaidGrant` 作为精确到单次书籍任务、操作 SHA、用途、冻结计划和下一个候选序号的**独立、额外付费授权凭据**。记录批准人、额外请求可用资源单位和到期时间，且须由仍有效的工作区 OWNER 批准。保存 `requestedEnabled` 偏好**不能创建此授权**。

`reserveFirstBookFailoverSwitch` 是内部服务方法，不是 HTTP 接口、不是第二次模型调用。其数据库事务复核：

1. 当前 Book Run/Job 的执行 Claim、租约、代次、用户和工作区。
2. 新旧候选属于同一冻结、有效的模型计划；备用模型端点、协议、连接、密钥版本仍有效。
3. 原始文本请求和备用请求完整内容指纹完全一致，不允许偷偷改提示词或提高配额后冒充原请求。
4. ProviderInvocation 必须是 Gateway 显式释放的 `PENDING` 状态、没有活动 Claim、没有任何 Attempt，且与先前保留的 ID 精确一致。这条证明依赖既有 Gateway 的硬不变量：它会先持久化 Attempt，然后才调用网络适配器。没有 Invocation、存在任意 Attempt、结果未知或审核拒绝均不得预留。
5. 独立 OWNER grant 真实存在、未过期、未被消费、明确覆盖本次追加资源需求。
6. 根据同一租户的全部未结算与已结算资源单位，重新核对日限额和单 Run 限额。后续真正执行时，Provider Gateway 还会再次在数据库中原子进行资源预算预留。
7. 复用 `assessProviderFailover` 对失败代码、模型能力、次数和第二模型资格作最终判断，仅在满足全部门禁时，使用 Revision CAS 原子写入 `candidateIndex=1`、`switchesUsed=1`、`state=SWITCH_RESERVED`，并冻结唯一备用请求幂等键；同事务仅消耗一次 grant。

## 强制安全边界

- **没有授权签发 HTTP/UI**：不存在默认生成授权、默认付费授权、后台自动签发，也没有用户端能通过普通偏好直接写入它。
- **未触发任何备用模型请求**：目前还没有从 `SWITCH_RESERVED` 取出候选并执行 Gateway 的生产 Worker。仅在测试数据库中通过人工构造的独立授权验证事务行为。
- 现有 `FrozenBookFailoverPlan.executionEnabled=false` 不变；不会把此前的主模型切换成新模型，也不会修改播客和短视频。
- 只处理第一跳（第 0 个主模型到第 1 个备用模型）；第二跳、自动额外付费授权的交互、实际模型调用与回执对账仍未实现。
- **明确拒绝内容审核绕过、未知计费结果和活动远端尝试**。已发生内容审核拒绝的记录不能通过后续重新归类擦除阻塞。
- 资源单位是上界估计，不是人民币或美元计价；独立货币预算/用户收费上限仍需要产品层授权和真实价格表审计，不能凭资源单位推算精确费用。

## 验收要点

新增真实 PostgreSQL 回归检查无 grant 拒绝、租户/工作区隔离、有效 OWNER 授权、一次性授权消费、CAS 防重复切换、备份固定幂等键以及不允许主模型再次重投。所有验证不触发外部 AI、没有生产部署或付费请求。

下一步不是继续新增重复的审计阶段，而是建设**授权签发入口及清晰的追加付费上限交互**，再将已预留的独立调用连接到实际 Worker，完成 Fake Gateway 模型自动切换纵切验证。
