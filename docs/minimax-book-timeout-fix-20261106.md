# MiniMax M3 书籍请求超时修复

## 真实问题定位

当前《反脆弱》的正文已提取成功。AI 分块理解存在两轮失败调用，每轮三个远端尝试，全部在约 30006～30025 毫秒时因 TIMEOUT 结束。没有收到可用分块结果或可确认 Token 用量；超时不代表供应商未处理或未收费。原始账本和任务保留。

运行代码未为该模型提供专门执行策略，采用通用 30 秒、最多三次的默认值。这是已确认的本地中断与重复请求机制，不能据此断言供应商一定会在更长等待内成功。额外无密钥 GET 连通检查中，MiniMax 国内、国际模型目录均在约 0.3～0.5 秒返回 401，说明检查时网络可达；未调用生成接口。

## 修复范围

- Worker 为 MiniMax-M3 的 BOOK_CHUNK_ANALYSIS、BOOK_REDUCTION_ANALYSIS、BOOK_SYNTHESIS 提供可信运行策略：默认 120 秒、最多一次尝试。其他模型、Embedding、音频、播客、视频沿用原设置。
- Gateway 接受可信执行依赖提供的策略，现有显式操作超时/次数覆盖仍优先，单请求预算次数仍取更小值。策略不进入正文、冻结路由或请求指纹，保留历史身份、回执、幂等及预算预留逻辑。
- 使用该策略时，并发租约至少覆盖等待时间加 1 秒；原执行认领心跳、取消和预算检查保留。超时不释放已发送请求的未知成本预留。
- 页面将 TIMEOUT 显示为“理解超时”，解释已停止、结果保留与扣费未知，提示勿连续恢复，并展示安全错误编号。后台服务在线与模型调用失败分开显示。
- 不自动重启或恢复原失败任务，不修改历史数据库或收费记录。
