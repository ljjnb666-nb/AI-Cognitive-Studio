# 书籍深度理解：发送前意图与只读回执恢复

## 为什么需要本补丁

#249 已持久化逐操作的故障切换账本，但 Worker 若在 Gateway 执行后、记录失败观察前发生进程级崩溃，则仅有初始检查点，尚不能凭初始记录断言远端请求没有发送。尤其失败重投更换 Job ID、生成新的 Gateway 幂等键时，存在重复付费风险。

## 本次实现

1. 新增 `sendIntentKey`、`sendIntentInputHash`、`sendIntentAt` 三个可空数据库字段，SQL 约束三者同时存在或同时缺失；旧账本不虚构这些字段。
2. Worker 在调用主模型前，持有 Book 当前执行租约，事务中原子登记唯一 Gateway 幂等键和完整出站文本请求的哈希。**事务成功提交之后**才允许发送模型请求。
3. 同一操作后续重投不可能重新获得首次发送许可。原先没有意向登记的历史账本同样不推断为安全重发。
4. 若原调用有已成功持久化的文本回执，且工作区、用途、原模型、连接与凭据版本均匹配，则返回原始 Invocation ID 与 Snapshot ID，直接由本地 ProviderExecutionRepository 解密并验证原文本回执；**只读恢复分支不进入 Gateway.execute 或 Provider Adapter**。
5. 未找到匹配的成功回执、远端结果未知、旧账本缺少预发送身份、输入指纹改变、租约失效、计划损坏时，直接阻塞；不能新建收费调用。
6. 发送前已登记意图的操作，失败观察时即使暂未看到 ProviderInvocation，也始终分类为费用未知，而不是根据数据库查询空值推断为未发送。
7. 仍以 `executionEnabled=false`、`candidateIndex=0`、`switchesUsed=0` 运行，无备用 Provider 的自动调用。

## 核心不变量

- 一项操作只有首次原子预留者能够尝试主模型。
- 二次进入必须读取到符合冻结路由的 **成功原回执**，否则永远不通过网关重发。
- 恢复有结果但已消费或密文不存在时，只能停止并等待人工检查。
- 新 Job ID 不改变已冻结的原请求身份；重新选择模型或换用不同提示词不得冒充旧回执。
- 数据库和 Worker 的租户 / Job / 执行代次 / 租约检查持续生效。
- 本改动不修改播客、短视频、TTS、向量语义或用户 UI。

## 回归

原有 Phase 2 真实 PostgreSQL 回归增加：首次预约、重复请求、Job 换号、请求内容漂移、在 Gateway 建立 Invocation 前崩溃、未结算失败、旧无意向账本保持阻塞，以及通过合成真实加密文本回执进行无网络恢复。既有完整 CI 对静态类型、容器和媒体链路执行非付费验收。

## 后续工作

这是 crash-safe 的书籍主模型**发送防重复基础**，不是已可用的自动模型降级。要启用第二模型，仍需任务级明确预算/付费授权、可验证的前次收费结算、操作级切换 CAS 预留、候选网关 Invocation 独立血缘、撤权/并发/停机恢复测试。不得用“用户保存了备用偏好”代替收费授权。
