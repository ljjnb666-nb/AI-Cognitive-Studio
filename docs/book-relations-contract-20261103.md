# Book 关系索引契约修复与离线验收

本次只修复和测试关系索引契约，没有新增真实云端请求或费用。

## 问题及最小修复

前次单次真实复测的 JSON 已完整返回，但 6 条记忆中出现了 `fromOrdinal=6`。合法数组索引是 0～5。旧提示只写“整数”，没有明确从 0 开始；编号形态可能来自不同索引习惯，不能据此自动减一或猜测关系映射。

- 在共享分析模块定义关系契约：关系两端必须引用**同一响应的 memory 数组**，从 0 开始；不能引用输入记忆、来源块或分块序号。给出 6 条记忆的 0～5 示例；没有记忆时关系必须省略或为空。
- JSON 模式和严格结构化模式都发送同一契约说明。
- 新生成结果通过共享 `assertAnalysisRelationsWithinMemory` 校验；拒绝负数、非安全整数、超出数组长度以及没有记忆却存在关系的结果。
- Gateway 返回业务结果前、持久化回执消费时，以及非 Gateway 的受保护生成入口都使用该校验。拒绝整份无效响应，不重编号、不删除错误关系、不自动重试。
- `book-relations-zero-based-v1` 写入请求输入哈希和快照 schemaVersion，明确区分新契约。旧已结束的授权不会因此恢复；同一旧幂等键下输入不匹配会安全拒绝，不能盲目重发。未来真实复测需要新的合法 Job/授权及 Prompt 版本。

历史冻结产物仍使用原有结构解析，不回写旧响应，不把旧关系自动转换成新格式。本次没有重跑分块或迁移历史数据。

## 实际验证

- Book 单元回归 **49/49**：包括索引 0 与末项、六条记忆使用索引 6、负数、小数、非安全整数、缺少记忆、原对象不变、无效关系不重试且不写归并缓存。
- Worker PostgreSQL/Gateway 回归 **48/48**：两种输出模式均携带零基索引说明；非法结果不返回业务层、不消费回执；相同失败请求回读回执时仍拒绝，不再次请求供应商；版本标记入快照；既有冻结恢复相关测试继续通过。
- 合计 **97 项**，没有把前轮重复运行的测试再计入。
- 两个包 TypeScript、修改文件 ESLint、`git diff --check` 通过。
- 对前次真实回执离线重放，精确复现 `ANALYSIS_RELATION_INVALID`，原始文件 SHA256 不变。
- 对私有分块验收库执行只读核验：141 个冻结产物仍可按原契约读取，所有原始行哈希及 16 条旧授权记录哈希不变。

私有回执、原书内容及身份清单不提交仓库。此处没有宣称真实模型现在会稳定遵守新契约。
