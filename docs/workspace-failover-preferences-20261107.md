# 统一降级第二阶段：备用模型配置与持久化（2026-11-07）

## 当前交付

在主干已经合并的跨流程降级策略之上，新增可持久化的工作区备用方案：

- 在服务商设置的高级区按 11 个支持 Provider Gateway 的用途保存最多两项备用模型；
- 默认无偏好记录、自动执行关闭，显示“预配置”“自动执行未启用”；
- 保存要求工作区 OWNER 权限、ACTIVE 服务商和凭据、模型目录能力匹配，不能保存与当前显式主路由重复的模型或同一候选两次；
- 版本号和期望版本（CAS）阻断多标签页覆盖；更改写入 ProviderAuditEvent；无密钥/原文写入偏好或审计；
- GET 返回经过能力过滤的可选模型，API 和 UI 不会调用模型；
- 采用独立 PostgreSQL 表，迁移默认不创建任何预选项；删除工作区时配置随之清理。

## 配置不等于自动执行

新存储字段 `requestedEnabled` 只表达**用户希望未来启用**。所有 API 响应的 `executionEnabled` 固定为 `false`，没有 Worker 读取这张表来自动调度备用模型。真实自动切换必须满足：

1. 新任务创建时读取现有偏好、再次核验工作区、凭据与模型能力，和主路由一起冻结完整候选计划，不能影响旧任务；
2. Gateway 调用失败后先完成收据、费用和租约对账，按 `assessProviderFailover` 的规则决定是否可切换；
3. 在各自 Durable Worker 里创建具有独立模型身份和父调用血缘的新 invocation；只有在预算和授权都有效时才能发出额外请求；
4. 向量化只能整体重建并原子切换索引；音频需要音色/格式映射；PDF 视觉需要单独许可；语义审校不能失去独立性；
5. 审核拒绝、未知费用状态、重复计费风险或撤权必须停下，不允许利用模型切换绕过内容安全限制。

此阶段不包含任何付费 API 请求、生产部署或主干合并，也不能宣称“全流程自动降级完成”。

## 验收门禁

需通过 Prisma schema/migration、静态类型检查、Web 真实 PostgreSQL API 集成测试、无外部模型调用断言、原有 Beta/UI/主干 CI。以上均是工程验证，不能替代真实收费调用或故障场景 E2E。
