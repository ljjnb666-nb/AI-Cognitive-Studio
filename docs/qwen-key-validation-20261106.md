# 百炼密钥验证修复（2026-11-06）

## 根因与修复

原验证逻辑只有固定供应商验证地址，没有百炼工作区专属模型目录地址。前端验证请求也未携带已填写的百炼区域、工作区配置，因此返回“不支持自动验证”，并非云端判断密钥无效。

前端现将区域与工作区配置随验证请求提交。服务端使用既有白名单区域与工作区格式校验，要求调用地址与配置精确一致，推导同一官方主机的 `/api/v1/models` 地址。仅发送 GET，禁止重定向，不发送模型生成请求，不保存测试密钥，不自动绑定用途。

HTTP 200 仍须满足 `success: true`、`output.models` 数组和非空型号标识校验。认证拒绝、网络错误、超时沿用现有安全状态；供应商原始回执不向页面或日志透传。

## 验证

- 使用用户明确提供的北京工作区配置，进行了两次真实模型目录 GET 查询，均 HTTP 200。
- 第一次确认响应包含模型目录；第二次核验 `success: true` 和新增目录结构校验均满足，每页返回 20 项。
- 没有聊天生成、Embedding、TTS、视频或 OCR 调用。目录访问成功不代表每个模型的推理权限或生成质量已经验收。
- 离线及独立测试数据库回归：2 个文件、51 项通过，包括新增北京/新加坡目录地址、异常成功响应拒绝、配置缺失及地址不匹配时不发密钥。
- TypeScript、变更文件 ESLint、Git 空白检查通过；本机服务健康检查 200。
- 保留用户原有 `apps/web/AGENTS.md` 修改，未修改历史任务、用途绑定或生产数据库。
- 本文不包含真实密钥、工作区身份或供应商原始回执。
