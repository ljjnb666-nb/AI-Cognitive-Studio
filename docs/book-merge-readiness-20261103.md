## 已实施修复

- `frozen-chunks.ts`：从当前用户有权访问的同书、同提取版本、同分块集合，按顺序选取完整成功分块；校验内容哈希、来源重构、范围、终态来源 Run 和已消费成功回执。新 Run、Job、冻结清单与导入产物同事务建立，不修改旧产物或账目。
- `pipeline.ts`：复用既有分析管线；冻结清单进入独立语义身份；恢复保留原始来源清单，执行前再次校验；并发创建返回同一合法任务。
- `analysis.ts`：父阶段接收派生摘要、记忆及其证据定位；多轮归并和缓存返回完整结构化结果，保留记忆及关系。不同父节点、层次和批次使用不同请求身份，相同操作重放保持稳定。
- `pipeline.ts`：未核验直接引文不进入父阶段的有效引文视图，原始响应不变；书级记忆保留同提取版本内的合法来源证据，拒绝外书及越界证据。
- `merge-quality.ts`：提供只读结构门禁 `inspectBookMergeStructure(runId)`，检查冻结来源、层级闭合、分块覆盖、记忆来源和向量覆盖；始终返回 `semanticReviewRequired: true`、`fullBookVerified: false`，不将结构通过当成语义验收。

## 正式质量门禁

结构门禁以 `inspectBookMergeStructure` 的 `structuralPass` 和空 `issues` 为必要条件。以下人工语义核验也必须全部完成，才能给出全书业务验收结论：

1. 对每个实际 SECTION/CHAPTER 建立来源到父摘要的核对表，覆盖率 100%；标题段与实质论据分开，不能把只有标题的块当完整论证。
2. 每个实质章节至少核对 3 个关键论点；少于 3 个则全查。全书明确主张、关键数字、年代、人物归属和限定条件逐项核查。要求关键论点覆盖率至少 95%，重要事实及限定条件错误为 0；遗漏须明确登记，不得靠猜测补足。
3. 每条用于结论或后续播客的事实必须记录源块、偏移、支持关系、作者观点/引用/分析推断分类和核对人；重要事实支持率 100%。无证据的推断不得写成原著事实。
4. 拟使用的直接引文全部逐字、逐范围核验，合格率 100%；不合格候选保留原件并隔离，不静默修补或降格冒充成功。
5. 逐章核对反例、适用边界和前后关系；重大矛盾、虚构关联、跨谱系内容为 0。全书总结须组织核心论证，不以逐段拼接代替综合。
6. 使用现有 Book Memory 形成书籍主题、核心思想、论证、案例、局限五项内容提纲，并逐项给出来源。此处只审核播客可用性，不生成脚本、音频或视频。
7. 任一 P0 或未完成核对均阻断 `FULL_BOOK_VERIFIED`。机器结构通过、Mock 成功或 Run=SUCCEEDED 均不能替代人工质量结论。
