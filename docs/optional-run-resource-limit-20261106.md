# 取消当前工作区单任务资源上限

按用户明确要求，关闭当前工作区的单任务累计资源单位限制。每日额度、请求大小、模型输出额度、权限与费用授权检查继续生效；本轮未恢复收费任务。

## 实施

- 增加 `WorkspaceResourcePolicy.runLimitEnabled`，默认 true。原有数值（包括零）仍保留原义，不以无限大数字替代取消。
- 预算预留在开关为 false 时跳过单任务累计限制，每日限制仍在原事务与行锁内执行，未知费用预留不释放。
- 所有者设置接口可读写布尔开关；省略字段的旧客户端更新不会把已关闭的上限重新启用。其他工作区默认仍启用。
- 设置页显示“启用单任务上限”开关，关闭时保留并禁用原数值输入，明确每日额度继续生效。
- 新增非破坏性迁移，仅添加默认 true 的布尔字段。先在独立测试库应用，再核验本机库没有其他待执行迁移，仅应用本次迁移。没有合并主分支或部署远端环境。

## 当前工作区实测结果

- `runLimitEnabled=false`，原数值 300000 仍保存但不参与单任务拦截。
- 每日上限保持 1000000。
- 配置更新前后资源预留条数、原始预留单位和已结算/未知合计均不变。
- 更新前配置和核验结果保存在私有验收目录，未包含密钥。

## 验证

- PostgreSQL 预算回归 2 项通过：原并发预留保护；关闭单任务上限后每日上限继续执行，未知预留保留，重新启用零额度仍拒绝。
- 设置 API 回归 3 项通过：所有者取消、旧请求兼容、非所有者拒绝、非法开关输入拒绝。
- Web、Gateway TypeScript 与变更文件 ESLint 通过；Prisma schema validate 通过。
- Prisma generate 已生成新增客户端字段，但最后替换运行中的 Windows DLL 返回 EPERM。待生成引擎和现有引擎 SHA-256 完全一致；保留现有引擎，不停止无关进程。上述真实数据库测试使用新增字段通过，未将生成命令本身记为成功。
- 按前端调试技能使用 Playwright（Browser 插件不可用）验证实际设置组件及模拟接口：关闭提示、禁用数值、重新启用及保存请求均正确。
- 本机健康检查 200；现有 Worker 子进程已在代码变更后重新加载。未清库、删除历史记录、取消每日额度或触发模型调用。
