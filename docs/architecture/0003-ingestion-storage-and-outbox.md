# ADR 0003: Ingestion storage and outbox

Original bytes, temporary uploads, and extracted text live in a private S3-compatible store behind `StorageProvider`. Server-side calls use the internal `S3_ENDPOINT`; browser presigned PUT URLs are created by an AWS SDK v3 client configured with `S3_PUBLIC_ENDPOINT ?? S3_ENDPOINT`. Signed URLs are never host-rewritten after signing. Local and test storage use MinIO Community with an explicit server-level `MINIO_API_CORS_ALLOW_ORIGIN=http://localhost:3000` setting, validated by real browser-style preflight requests. Community MinIO does not provide the AIStor per-bucket CORS management contract; production storage may use an S3-compatible implementation that does. PostgreSQL stores metadata, object keys, hashes, parser versions, lifecycle state, and offsets only.

Upload completion treats uploaded bytes as untrusted data, never as instructions. It streams the temporary object once to calculate its actual byte count and server-side incremental SHA-256, retaining only a 64 KiB sniff prefix. The canonical key `workspaces/<workspaceId>/source-blobs/<sha256>` is content-addressed and private. A newly copied canonical object, or an orphan object found at that key, is streamed and verified against the digest and size before any database identity is created. A known corrupt pre-existing canonical object is preserved and fails integrity validation rather than being overwritten. `SourceBlob` deduplicates exact canonical bytes, while each `SourceDocument` retains its own resolved media type and therefore parser interpretation: identical TXT and Markdown bytes can share one blob without sharing interpretation metadata.

`getObjectBytes` is transitional compatibility for the current parser input path; upload completion is streaming. Upload completion uses a `COMPLETING` claim guarded by PostgreSQL `NOW()` leases, and the `SourceBlob` unique key converges concurrent identical uploads without sharing source interpretation. Temporary cleanup only targets `temporary/` upload keys; canonical source blobs have no automatic garbage collection.

Completing an upload writes the source document, durable job, ingestion run, and outbox event in one database transaction. The dispatcher claims events with PostgreSQL `NOW()` leases and ownership tokens (`PENDING`/`PROCESSING`/`DISPATCHED`/`FAILED`), enqueues the deterministic run id in BullMQ, then finalizes only with the same token. This is at-least-once transport, not exactly-once; PostgreSQL `Job` remains the business authority and the processor is idempotent. PDF parsing runs outside the worker in an isolated boundary and EPUB parsing rejects unsafe archive/XML input; neither parser performs network fetches.
