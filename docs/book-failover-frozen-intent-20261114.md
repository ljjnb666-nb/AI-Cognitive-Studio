# 新书理解：冻结主备模型意向（2026-11-14）

## 本次新增

- **仅为新创建的 Book Analysis 作业**：在已有四用途主路由快照之上，读取同工作区已保存且“希望未来启用”的三项文本用途备用顺序。
- 按用途冻结主模型作为序号 0，以及最多两项备用模型。保存 provider/model/connection/active credential version、端点与非敏感配置，附偏好版本和双重完整性指纹。
- 只接受 ACTIVE 连接与凭据、HTTPS 端点、符合用途能力的模型。拒绝重复模型、无效配置、密钥字段、失效偏好哈希和不可验证的快照。
- 将新作业的 `failoverPlan` 保存到 PostgreSQL Job.payload；同时由 Worker 每次重入时只读核对其主路由绑定和完整性。重投时保留原作业的计划，不根据工作区当前最新偏好悄悄替换。
- 只处理 BOOK_CHUNK_ANALYSIS、BOOK_REDUCTION_ANALYSIS、BOOK_SYNTHESIS。embedding、审校、播客、短视频、TTS 的安全执行策略暂不接线。

## 本次刻意未启用

- `executionEnabled` **强制为 false**，无实际备用 Provider Gateway 调用，不产生额外付费，不绕过内容审核，不改主模型；
- 没有新的 Worker 自动切换、候选索引/切换次数状态写入，也没有跨模型费用收据对账；
- 保存了“未来启用”偏好不是独立的付费授权。对审核拒绝、未知收费状态、欠费、超时等情形，现有任务仍然走原有失败/恢复路径，不宣称自动降级已经完成。

## 不变量和边界

- 历史任务没有 `failoverPlan` 时保持原执行路径。
- 已存在相同分析身份的任务直接复用原作业，永远不替换其已冻结的计划；不为备用意向变化单独制造重复收费的理解任务。
- 对已冻结计划的失败重投沿用原主路由及备用计划，数据不一致时拒绝执行；无新付费授权，不能自动切换。
- 数据库迁移沿用已合并的 #245，不增加迁移或改变现有 UI/API 合同。
- 未来启用必须先实现：任务级预算和权限批准、每次调用回执/账单确认、候选索引和切换次数持久化原子更新、独立调用血缘、停机重投和撤权竞态测试。

## 验收

需在准确 HEAD CI 中检查类型/Lint/单元/真实 DB/现有 Web、Worker、媒体链路回归。新增确定性单测不触发外部付费 API；单元通过不代表自动切换已上线。禁止未经授权部署、收费测试或合并。
