# MiniMax 国内站密钥验证修复（2026-11-06）

## 根因

前端已提供国内站 `https://api.minimax.cn/v1/chat/completions`，后端保存/验证却只接受国际站旧地址。请求在调用供应商前即被本地端点检查拒绝。验证资源表也未接入 MiniMax，Gateway 的执行地址白名单同样遗漏国内站，因此不能只修表单。

## 修复

- 表单与服务端共用固定站点配置；国内站验证请求仅发送至国内站 `GET /v1/models`，国际站仅至国际站对应接口，不跨站回退。
- 验证不再把 HTTP 200 直接判定为有效：必须返回合法模型列表；401/403、异常 JSON、错误结构分别处理。
- Gateway 增加国内站固定文本端点；按已冻结端点精确选择 Profile。原国际站默认、旧快照与既有配置不改写，非白名单地址继续阻断。
- 保存服务商不自动绑定用途或调用模型。

## 真实检查

用户提供的密钥通过隐藏输入进入一次性检查进程，仅保留在内存；未写入源码、私有脚本、报告、数据库或日志。仅向国内站发送 1 次 GET 模型列表请求，禁止跟随跳转，无自动重试：HTTP 200，模型列表结构有效，共 9 个型号，包含 MiniMax-M3。未发送文本生成、Embedding、TTS、视频或 OCR 请求。没有调用国际站测试该密钥。

## 验证

- 网页 TypeScript 与修改范围 ESLint 通过。
- 网页接口回归 3 文件 42/42；数据库仅使用独立测试库的新建测试记录。
- Gateway 单元/Adapter 回归 3 文件 60/60，包含国内站模拟调用、国际站旧端点、冻结快照不变及非批准地址阻断。
- 浏览器插件不可用，沿用真实组件 Playwright 隔离验收，使用测试假密钥：切换国内/国际站提交正确端点，验证成功消息正常显示。浏览器接口为模拟，不冒充真实密钥请求。

官方依据：https://platform.minimax.cn/docs/api-reference/models/openai/list-models 与 https://platform.minimax.cn/docs/api-reference/text-openai-api 。
